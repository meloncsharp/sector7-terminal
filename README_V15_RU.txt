UFILAG v15 — ИСПРАВЛЕНИЕ ПУБЛИКАЦИЙ И КОММЕНТАРИЕВ

Что исправлено:
- Комментарии: обработчик теперь подключён через делегирование событий, потому что карточка статьи создаётся динамически после загрузки из Supabase. После успешной вставки комментарии перечитываются и отображаются.
- Комментарии: добавлены понятные сообщения при отсутствии таблицы, ошибках авторизации и RLS.
- Публичный контент: ошибки чтения Supabase больше не маскируются демонстрационными данными — показывается понятное сообщение о проблеме подключения.
- Админка: удалён дублирующий блок главного экрана с повторяющимися HTML id, из-за которого браузер и JavaScript обращались к неправильной форме.
- Миграция: добавлен единый идемпотентный SUPABASE_V15_REPAIR.sql. Он создаёт недостающие основные таблицы, комментарии, grants и RLS policies, не удаляя существующие записи.
- Разрешены типы публикаций news, announcement, trailer, devlog, article и update.

УСТАНОВКА:
1. Сделайте резервную копию базы Supabase (Dashboard → Database → Backups, если доступно).
2. Откройте SQL Editor и выполните SUPABASE_V15_REPAIR.sql. Скрипт рассчитан на повторный запуск и не удаляет контент.
3. Убедитесь, что Storage bucket ufilag-media создан и отмечен Public.
4. Замените файлы сайта содержимым этого архива.
5. Откройте сайт с жёстким обновлением (Ctrl+F5).
6. Войдите в аккаунт, откройте существующую новость через её карточку, оставьте комментарий.

ВАЖНО:
- Для комментариев пользователь должен войти в аккаунт.
- Публичный контент читается анонимно, но запись/редактирование доступна только аккаунту с role=admin.
- В Supabase проверьте, что у вашей записи в public.profiles поле role равно admin.
- Реальную работу с вашим проектом Supabase невозможно подтвердить без запуска миграции и браузерной проверки на вашем проекте.
